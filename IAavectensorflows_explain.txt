IAavectensorflows.py - explication detaillee
===========================================

But du script
-------------
Ce script entraine un modele TensorFlow pour predire la probabilite de victoire
depuis un etat de partie Pokemon (format OU), a partir des fichiers
ou_winrate_chunks/ou_winrate_data_*.json.

Il charge les etats, fabrique des features numeriques + embeddings, entraine un
reseau dense, evalue sur un set de validation, puis sauvegarde le modele.


Structure globale du fichier
----------------------------
1) Imports, constantes et tables de conversion.
2) Fonctions utilitaires (normalisation, hash, type chart, vitesse).
3) Dataclass FeatureConfig.
4) FeatureBuilder: construit les features pour chaque exemple.
5) Iterateurs et split des fichiers.
6) tf.data.Dataset.
7) Construction du modele TensorFlow.
8) Save/load de config.
9) Train et Predict.
10) Parse des arguments + main.

Fonctions utilitaires de texte / hash
-------------------------------------

normalize_species_name(name)
- Nettoie le nom: lower-case, supprime caracteres non alphanumeriques.
- Utilise pour matcher un nom dans le pokedex.

normalize_token(token)
- Nettoyage generique pour status, moves, side conditions.

stable_hash(token, dim)
- CRC32 pour obtenir un indice stable dans un espace de dimension dim.

hash_tokens(tokens, dim)
- Cree un vecteur float dim.
- Pour chaque token, ajoute +1 dans la case hash.
- Sert a encoder les side conditions et les last moves sans vocabulaire fixe.


Fonctions utilitaires pour les types
------------------------------------

normalize_type_name(type_name)
- Convertit un nom de type en forme canonique (ex: "fire" -> "Fire").

type_multiplier(attacker_type, defender_types)
- Multiplie les effets du TYPE_CHART pour un type attaquant.
- Retourne 1.0 si inconnu.

best_type_multiplier(attacker_types, defender_types)
- Prend le meilleur multiplicateur parmi les types attaquants possibles.

speed_multiplier(boost)

- Respecte la formule Pokemon standard.

FeatureConfig (dataclass)
-------------------------
side_hash_dim, move_hash_dim, volatile_hash_dim, turn_cap
- Taille des vecteurs hashes et normalisation du tour.


FeatureBuilder
--------------
Classe centrale qui transforme un exemple JSON en features tensors.

__init__(config)
- Construit les mappings de types, status, weather, terrain.
- Calcule numeric_dim et global_dim.

_numeric_dim()
- Compte les colonnes numeriques par Pokemon:
  hp, fainted, revealed, is_active, stats base, poids,
  volatiles count + hash + has_substitute.

_base_global_dim() / _matchup_dim()
- Taille des blocs "global" (etat general + features de matchup).

_global_dim()
- Somme: side_hash (2x) + move_hash (2x) + base_global + matchup.

_team_order(team, active)
- Assure que le Pokemon actif est place en premier.
- Complete avec des slots vides jusqu'a 6.

_pokedex_entry(species)
- Cherche l'entree du pokedex a partir du nom normalise.

_species_id(species)
- Retourne un id pour embedding; 0 si inconnu.

_type_ids(entry)
- Retourne (type1_id, type2_id) pour l'entree pokedex.

_base_stats(entry)
- Retourne les stats base normalisees /255.

_active_boosts(boosts)
- Convertit les boosts de l actif en valeurs [-1, 1] (clip -6..6 puis /6).

_status_id(status)
- Encode le status en id.

_volatile_features(volatiles)
- Compte les volatiles, hash dans un petit vecteur, detecte "substitute".

_find_team_member(team, active_name)
- Retrouve le Pokemon actif dans le dict, meme si le nom a un format
  different. Fallback sur le premier matching par nom normalise.

_estimated_speed(entry, boosts)
- Base speed * multiplicateur de boosts (approximation sans items/abilities).

_team_matchup_ratios(team, opp_types)
- Parcourt l'equipe, calcule si chaque membre est faible (>=2x) ou resistant
  (<=0.5x) face aux types adverses actifs.
- Retourne ratios faible/resistant.

build_example(example)
----------------------
Etapes principales:
1) Recupere state, equipes, actifs.
2) Identifie les actifs et leurs types via pokedex.
3) Pour chaque Pokemon (12 slots):
   - species_id, type ids, status id
   - features numeriques (hp, fainted, revealed, is_active, stats base,
     poids, volatiles, etc.)
4) Features globales:
   - side conditions hash (ours + opp)
   - last moves hash (ours + opp)
   - turn, hp moyens, fainted ratios, revealed ratios
   - features de matchup:
       * hp actifs + diff
       * vitesse estimee + diff + avantage binaire
       * boosts des actifs (atk/def/spa/spd/spe) pour les 2 joueurs
       * meilleurs multiplicateurs de type actif vs actif
       * ratios equipe vs types adverses
5) Assemble un dict de arrays numpy + label winner (float).

output_signature()
------------------

- Indispensable pour que TensorFlow connaisse la structure en avance.


Iterateurs et split
-------------------
iter_examples(file_paths)
- Lit chaque fichier JSON et yield chaque exemple.

iter_filtered_examples(...)
- Applique un split "example" (1 example sur N) ou "file" (pas de filtrage).
- Permet aussi un max_examples pour limiter la taille.

split_files(...)
- Si split_mode = file, coupe la liste en train/val selon:
  val_file_count ou val_file_fraction.

compute_baseline(...)
- Calcule win_rate et acc majoritaire sur train/val.
- Sert a comparer au hasard.


make_dataset(...)
-----------------
- Cree un tf.data.Dataset a partir du generator.
- Shuffle uniquement sur train.
- La validation est separee par fichier (par defaut) ou par example.


build_model(...)
---------------
Inputs:
- species_ids, type1_ids, type2_ids, status_ids (embeddings)
- numeric_feats (features par Pokemon)
- global_num, weather_id, terrain_id (features globales)

Architecture:
- Embedding species (dim 16)
- Embedding types (dim 4) et addition type1 + type2
- Embedding status (dim 3)
- Concat per-Pokemon + flatten
- Embedding weather/terrain + concat global
- Dense -> Dropout -> Dense -> Dropout -> Sigmoid
- Regularisation L2 optionnelle sur les Dense.

Compile:
- Optimizer Adam lr=1e-3
- Loss: binary_crossentropy (classification binaire)
- Metrics: accuracy + AUC.


save_config / load_config
-------------------------
- Sauvegarde les dimensions dans un json.
- Utile pour reconstruire exactement les features en prediction.


train(args)
-----------
1) Fixe les seeds (random, numpy, tensorflow).
2) Charge les fichiers de donnees.
3) Split train/val (par fichiers par defaut).
4) Affiche baseline si demande.
5) Construit train_ds et val_ds.
6) Construit le modele avec hyperparametres.
7) Fit:
   - callbacks EarlyStopping + ReduceLROnPlateau sur val_auc.
8) Sauvegarde le modele:
   - Si --model_dir est un fichier .keras/.h5, enregistre la.
   - Sinon, enregistre dans dossier /model.keras.
   - Sauvegarde config.json a cote.


predict(args)
-------------
1) Charge le modele (model.keras ou fichier explicite).
2) Charge la config pour reconstruire les features.
3) Transforme les exemples en features.
4) Predict -> affiche win_prob.

Fonctionnement de l apprentissage TensorFlow (resume)
-----------------------------------------------------
1) Les fichiers JSON sont convertis en tensors via FeatureBuilder.
2) tf.data.Dataset cree un flux d exemples batche.
3) Le modele calcule une proba de victoire (sigmoid).
4) La loss binary_crossentropy compare proba vs label (0/1).
5) Adam ajuste les poids pour minimiser la loss.
6) La validation mesure generalisation sans modifier les poids.
7) EarlyStopping stoppe si val_auc n augmente plus.
8) Le meilleur modele est sauvegarde en .keras.


Conseils rapides
---------------
- Si val << train: sur-apprentissage. Augmenter dropout ou L2.
- Si les deux faibles: sous-apprentissage. Augmenter la taille du modele.
- Comparer toujours au baseline (0.5 si dataset equilibre).
